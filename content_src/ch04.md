## 강의 4장 다층 퍼셉트론(MLP)

**MLP**는 입력층과 출력층 사이에 은닉층을 하나 이상 넣은 신경망입니다(슬라이드 4). 각 노드는 3장과 같은 계산을 합니다. 입력에 가중치를 곱해 더하고 편향을 더한 뒤 **활성화 함수**를 통과시킵니다.

```math
\text{출력} = f\left(\sum_i x_i w_i + b\right)
```

코드로는 Linear를 이어 붙이는 것입니다. 슬라이드 4의 예처럼 3장의 `nn.Linear(1, 1)` 한 층이 `nn.Linear(1, 8)` → `nn.Linear(8, 1)`의 두 층이 됩니다. 8이 은닉층의 노드 수입니다.

### 왜 활성화 함수가 꼭 있어야 하는가

Linear만 두 번 쌓으면 식을 정리했을 때 Linear 한 번과 같아집니다.

```math
W_2(W_1x + b_1) + b_2 = (W_2W_1)x + (W_2b_1 + b_2)
```

그래서 층 사이에 **ReLU**(`$\max(0, x)$`)처럼 꺾이는 함수를 넣습니다. 이 꺾임 덕분에 층을 쌓을수록 휘어진 경계를 만들 수 있습니다. 강의에는 없는 내용이라 **추가 확인**으로 실행했습니다. 첫째는 직선 하나로 나눌 수 없는 대표 문제 **XOR**(입력 두 개가 서로 다를 때만 1)입니다.

⟪code:ch04_extra_checks:01⟫

- 3장 방식의 선형 1층은 넷을 모두 1로 찍습니다. 손실 0.6931(= `$\log 2$`)은 "반반으로 찍는 것"과 같은 수준입니다.
- 선형 2층도 ReLU가 없으면 풀지 못합니다.
- ReLU를 넣은 MLP만 `[0, 1, 1, 0]`을 맞힙니다.

둘째로 ReLU 없는 두 층이 정말 한 층과 같은지 숫자로 확인했습니다.

## 강의 4장 딥러닝 MLP 아키텍처

| 단계 | 하는 일 |

## 강의 4장 학습 데이터 MNIST와 실행 장치

**MNIST**는 사람이 손으로 쓴 0–9 숫자의 흑백 이미지입니다. 새 프로그래밍 언어를 배울 때 처음 찍어 보는 "Hello, World"처럼, 딥러닝을 처음 배울 때 거쳐 가는 데이터입니다(슬라이드 7–8).

검증 데이터는 학습률·모델 구조·Epoch처럼 **사람이 고르는 설정**을 정할 때 씁니다. 테스트 결과를 보고 설정을 다시 고르면 테스트 데이터가 사실상 검증 데이터가 되어, 진짜 처음 보는 데이터에서의 성능을 알 수 없게 됩니다.

## 강의 4장 배치와 Dataset · DataLoader

2·3장은 데이터 전체를 **통째로** 모델에 넣고, 예측과 정답을 통째로 비교했습니다. 데이터가 1만 행 × 1만 열처럼 커지면 문제가 생깁니다(슬라이드 11).

- 한 번에 계산하기에 **시간이 오래** 걸립니다.
- **메모리가 부족**할 수 있습니다.
- 전체 데이터의 기울기를 한 번에 계산하기 어렵습니다.

그래서 데이터를 32개, 64개처럼 작은 **배치**(batch)로 묶어 차례로 넣습니다. 이 일을 PyTorch의 두 도구가 나눠 맡습니다(슬라이드 12–13).

- **Dataset** — 입력 데이터와 정답을 저장합니다. `datasets.MNIST`가 이미 만들어진 Dataset입니다.
- **DataLoader** — Dataset을 배치 크기만큼 잘라 순서대로 건넵니다. 학습 데이터는 `shuffle=True`로 Epoch마다 순서를 섞고, 검증·테스트는 `shuffle=False`로 고정합니다.

```python
train_loader = DataLoader(train_dataset, batch_size=64, shuffle=True)
```

`train_loader`에서 꺼낸 배치 하나는 이미지 `[64, 1, 28, 28]`과 정답 `[64]`입니다. **배치 크기는 업데이트 한 번에 모델이 보는 샘플 수**입니다.

## 강의 4장 Batch · Iteration · Epoch

| 용어 | 뜻 | MNIST 예 |
|---|---|---|
| Batch | 한 번에 모델에 넣는 데이터 묶음 | 64장 |
| Iteration | 배치 하나를 학습해 W, b를 한 번 갱신 | 64장 학습 → 1회 갱신 |
| Epoch | 학습 데이터 전체를 한 번 모두 학습 | 55,000장 1바퀴 |

```math
\text{Epoch당 Iteration} = \left\lceil \frac{55{,}000}{64} \right\rceil = 860, \qquad 860 \times 5\ \text{Epoch} = 4{,}300\ \text{번 갱신}
```

`$\lceil\ \rceil$`은 올림입니다. 55,000이 64로 나누어떨어지지 않아 마지막 배치는 64장보다 적습니다.

⟪fig:ch04_batch|그림 4-4 · 배치 860개가 한 Epoch. 마지막 배치(노란 칸)는 24장입니다.⟫

## 강의 4장 손실 · 정확도 곡선과 테스트 평가

- **손실 곡선**(슬라이드 19) — 훈련 손실과 검증 손실이 함께 내려가면 정상입니다. 검증 손실만 다시 오르면 과적합을 의심합니다.
- **정확도 곡선**(슬라이드 20) — 훈련 정확도만 보지 않고 검증 정확도가 함께 오르는지 비교합니다.
- **테스트 최종 평가**(슬라이드 21) — 테스트 데이터는 학습 중 튜닝에 쓰지 않고, 학습이 끝난 모델의 최종 성능 확인에만 씁니다. 강의의 결과는 테스트 손실 0.0879, 정확도 97.46%(9,746 / 10,000)입니다.
- **실제 이미지 예측**(슬라이드 22) — 추론 단계에서는 Softmax로 클래스별 확률을 보고, `argmax`로 최종 숫자를 고릅니다.

실습 4-1이 이 과정을 그대로 실행합니다. 이 교재의 실행 결과는 강의 수치와 소수 셋째 자리 근처에서 조금 다릅니다. 라이브러리 버전과 장치가 다르면 같은 시드로도 난수와 계산 순서가 달라지기 때문입니다.

## 강의 4장 MLP의 한계와 CNN

MLP는 이미지를 **Flatten**해서 784개 숫자로 펼칩니다(슬라이드 23).

```text
MLP : MNIST → Flatten → Linear          픽셀을 긴 벡터 하나로 봄
CNN : MNIST → Conv2d → ReLU → Pooling    가로·세로 위치 관계를 유지하며 지역 패턴을 학습
```

펼치는 순간 "이 픽셀의 위·아래·옆이 무엇인가"라는 정보가 사라집니다. 같은 숫자가 몇 픽셀만 옆으로 가도 MLP에게는 전혀 다른 입력입니다. 실습 4-5의 마지막 실험이 이 한계를 숫자로 보여 주고, 5장의 CNN이 해결책입니다.

## 실습 4-2 Optimizer 비교 조건

**Optimizer**(옵티마이저)는 계산된 기울기로 가중치를 갱신하는 방법입니다. 차이를 Optimizer 탓으로 해석하려면 나머지를 모두 같게 둡니다.

```text
같은 데이터 + 같은 모델 구조 + 같은 초기 가중치 + 같은 미니배치 순서 + 같은 Epoch 수 → Optimizer만 변경
```

| Optimizer | 시작 설정 | 쉬운 해석 |
|---|---|---|
| SGD | lr = 0.1 | 지금 기울기 방향으로 이동 (2·3장 방식) |
| SGD + Momentum | lr = 0.1, momentum = 0.9 | 이전 이동 방향을 관성처럼 함께 반영 |
| Adam | lr = 0.001 | 매개변수마다 이동 크기를 따로 조절 |

모든 Optimizer에 같은 학습률을 준 실험이 아닙니다. 각자 흔히 쓰는 시작 설정으로 입문 수준의 특성을 비교합니다.

## 실습 4-3 과적합을 일부러 만드는 실험 설계

실습 4-3은 **과적합**(Overfitting)을 관찰하고 **Dropout**으로 줄여 보는 실습입니다.

| 상태 | 훈련 성능 | 검증 성능 | 해석 |
|---|---|---|---|
| 과소적합(Underfitting) | 낮음 | 낮음 | 모델이나 학습이 부족 |
| 적정 학습 | 높음 | 높음 | 새로운 데이터에도 잘 일반화 |
| 과적합 | 매우 높음 | 상대적으로 낮음 | 훈련 데이터를 지나치게 암기 |

MNIST는 쉬워서 과적합이 잘 드러나지 않습니다. 그래서 훈련 데이터를 **8,000장만** 쓰고, 은닉층을 크게(512, 256) 만들어 일부러 외우기 쉬운 조건을 만듭니다. 실제 프로젝트에서 데이터를 일부러 줄이는 것은 과적합 해결책이 아닙니다.

```math
\text{일반화 간격} = \text{훈련 정확도} - \text{검증 정확도}
```

간격이 클수록 훈련 데이터에 지나치게 맞춰졌을 가능성이 큽니다.

| Dropout | train()에서만 무작위로 끔, eval()에서 모두 사용 | 5장 |

1. `nn.Linear(784, 64)` → ReLU → `nn.Linear(64, 10)`의 학습 파라미터 수는?
